# 1本つくる(アプリ生成の入口)

ユーザーの指示1回 = ショート**1本**。テーマ選びは、この指示の前に `pick-themes` が済ませてある前提で、BACKLOG の「選定」から取る。ユーザーにテーマを聞き返さない。

## 流れ

1. **テーマを取る**
   - `public/shorts/BACKLOG.md` で、状態が「選定」の最上位を取る。
   - 「選定」がなければ、`pick-themes` を実行して選ぶ。
   - 状態を「制作中」にする。

2. **出典を照合する**(`verify-sources`)
   - 論文を開いて、書誌情報・主張・数字を確かめ、反論も探す。
   - 主張が成り立たない、または確かめられないときは、BACKLOG を「落選(理由)」にして、次の「選定」で1に戻る。ただし2回続けて落ちたら、そこで止めて、理由をユーザーに報告する。
   - 照合の結果は `SOURCES.md` に書く。

3. **つくる**(`make-short` の手順3〜5)
   - フック(問いで終える)、センターピン、字幕、描画を作り、`scenes.js` に追加する。
   - 撮影して目視で確認し、直す。

4. **公開する**(`make-short` の手順6)
   - コミットして `claude/cool-bell-864xoe`(指定のブランチ)に push する。
   - `python3 tools/shorts/bundle.py <新しい名前>.html` で1枚にして、**新しいリンク**で Artifact を公開する(旧版は上書きしない)。
   - BACKLOG の状態を「公開」に変え、`SOURCES.md` に行を足す。

5. **報告する**(短く)
   - 作ったテーマとフック、センターピンの瞬間。
   - 新しい Artifact のリンク。
   - 出典の状態(書誌確認済み/主張確認済み)と、見つかったズレ。
   - 確認できていないこと(あれば)。
   - 次の候補を1つ(BACKLOG の次点)。

## 守ること
- 1回の指示で作るのは1本だけ。続けて作らない。
- 出典の照合をとばして公開しない。
- 失敗したら(照合で落選、撮影でエラーなど)、途中までの状態と原因をそのまま報告する。
