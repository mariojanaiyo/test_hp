# 出典を調べて照合する

目的: 動画の面白さを保ったまま、**言い過ぎ・数字違い・古い説の断定**を公開前に潰す。
使う道具は WebSearch と WebFetch(ToolSearch で `select:WebSearch,WebFetch` を読み込む)。Crossref などの API はこの環境では通信が許可されていないことがあるので、前提にしない。

## 状態の定義(`public/shorts/SOURCES.md` の「状態」列)
| 状態 | 意味 |
|---|---|
| 未確認 | 記憶ベース。何も照合していない |
| 書誌確認済み | 著者・年・雑誌・巻ページ・DOI が実在の論文と一致 |
| 主張確認済み | 抄録か本文で、動画の核心の主張と数字が裏づけられた |
| 要修正 | 照合でズレが見つかった。直して再照合する |

「主張確認済み」になるまで、そのショートを「出典確認済み」と言わない。

## 手順(1本ずつ)

### 1. 照合する項目を書き出す
`scenes.js` の該当シーンから次を抜き出す。
- 核心の主張(フックとセンターピンが言っていること)
- 動画・字幕に出てくる数字と年代(例: 38兆個、1億8000万年前、24億年前、1995年)
- `source.cite` の書誌情報

### 2. 論文そのものを探す
- WebSearch に、論文タイトルと「著者 年 雑誌」を入れる。
- 見るのは出版社(nature.com、science.org、cell.com など)、PubMed、著者の研究室ページ、大学の公式発表、PDF。まとめサイトやブログは**手がかりにするだけ**で、根拠にしない。
- WebFetch で抄録/本文を開き、`prompt` に「この論文が何を示したか。使った動物・サンプル数・主な結果の数字」を入れて読む。

### 3. 書誌情報を照合する
著者(筆頭)・年・雑誌・巻:ページ・DOI が `source.cite` と一致するか。違えば `scenes.js` と `SOURCES.md` を直す。

### 4. 主張を照合する(ここで動画が言い過ぎていないかを見る)
- 論文が**実際に示したこと**と、動画の言い方を並べて比べる。
- よくあるズレ:
  - 動物実験の結果を、ヒトに当てはめて言っている。
  - 「相関」を「原因」と言っている。
  - 「可能性がある」を断定している。
  - 数字や年代が、後の研究で更新されている。
- ズレたら、フックと字幕を弱める(「？」型にする、「〜と言われる」を付ける)。`caveat` に差分を書く。面白さを捨てずに、断定だけ外す。

### 5. 反論・更新を探す
- 「論文タイトル + criticism / replication / reanalysis / review」で検索する。
- 総説(Review)や、その後の被引用論文で、結論が支持されているか、覆っているかを見る。
- 議論が続いている話題は、反対側の論文を1本は `caveat` と `source.cite` に入れる。

### 6. 記録する
`SOURCES.md` の行を更新する。状態、確認日、確認したURL、ズレと直した内容を書く。
```
| vole | … | Lim 2004 | 書誌確認済み (2026-10-28) | https://… 主張は未照合。著者の主張は「1遺伝子が一夫一妻を決める」より狭い → フックを弱めた |
```

### 7. 直して見直す
- 文言を変えたら `node tools/shorts/shoot.cjs <出力dir> <id> <時刻,…>` で、フックが2行に収まっているか、字幕のはみ出しがないかを撮って確認する。
- `git commit` して push する。公開済みの Artifact は上書きせず、必要なら新しいリンクで出し直す(`make-short` の手順6)。

## 報告のしかた
ユーザーには、次の形で短く伝える。
- 何本を、どこまで確認したか(書誌のみ / 主張まで)。
- 見つかったズレと、直した内容。
- 確認できなかったこと(本文が有料で読めなかった、など)。確認できていないものを「確認済み」と書かない。

## 守ること
- 検索結果の要約だけを根拠に「主張確認済み」にしない。論文の抄録か本文まで見る。
- 論文が見つからないものは、動画から主張を外すか、「未確認」のまま渡す。
- 恋愛・精神・健康の話は、ヒトで確かめられたことと動物実験の結果を必ず分けて書く。
